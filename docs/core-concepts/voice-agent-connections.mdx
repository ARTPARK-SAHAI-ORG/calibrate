---
title: "Voice Agent Connections"
description: "Run voice simulations against an external WebSocket voice agent"
---

Calibrate's voice simulation can connect to an **external** voice agent that runs its own [pipecat](https://github.com/pipecat-ai/pipecat) pipeline and exposes a WebSocket server — instead of using Calibrate's built-in (internal) agent.

This lets you simulate real audio conversations against an agent you've already built and deployed, with your own STT, LLM, and TTS wiring intact.

<Tip>
  If you want Calibrate to run the voice agent for you (defining `system_prompt`,
  `tools`, `stt`, `tts`, and `llm` in the config), use the built-in agent
  described in [Core Concepts: Agents](/core-concepts/agents) instead.
</Tip>

## How it works

In your voice-simulation config JSON, point Calibrate at your agent's WebSocket endpoint:

| Key                | Type   | Description                                                                                  |
| ------------------ | ------ | -------------------------------------------------------------------------------------------- |
| `agent_url`        | string | The WebSocket endpoint of your agent, e.g. `ws://host:port` or `wss://host:port`             |
| `agent_serializer` | string | Frame serializer used on the wire: `protobuf` (default)                                       |

When `agent_url` uses a `ws` or `wss` scheme, Calibrate does **not** spin up its own agent. The external agent owns the pipeline, so you do **not** need to provide `system_prompt`, `tools`, `stt`, `tts`, or `llm` — those keys are ignored on this path.

Everything else works exactly as in a normal voice simulation: `personas`, `scenarios`, `evaluators`, and `settings` behave identically.

## Protocol requirement

<Warning>
  The external agent must speak pipecat's WebSocket **frame protocol** using the
  **same serializer** as Calibrate (`protobuf` by default). In practice this
  means your agent should be a pipecat agent. The audio sample rate and encoding
  must also match. A bespoke, non-pipecat socket will not work unless it
  implements the same frame protocol.
</Warning>

Calibrate connects to your endpoint, streams the simulated user's audio as pipecat frames, and consumes your agent's audio frames back — so both sides must agree on the framing and serialization.

## Verify your connection

Before running, Calibrate performs a reachability check: it opens the WebSocket and confirms the handshake succeeds.

<Note>
  This check confirms only that the endpoint is **reachable** — it does **not**
  verify that the frame protocol or serializer is compatible. If your agent
  isn't a pipecat agent speaking the same serializer, the handshake can succeed
  while the conversation still fails to produce audio.
</Note>

## Metric caveats

The external WebSocket path measures real audio, but a few metrics differ from the built-in (internal) agent because Calibrate no longer owns the agent's pipeline:

<Note>
  **1. Per-processor latency is unavailable.** TTFT and `processing_time` for
  each processor (STT, LLM, TTS) come from the internal agent's own pipeline
  metrics, which an external agent doesn't expose to Calibrate.

  **2. Interruption is no longer a clean controlled variable.** With the
  built-in agent, `interruption_sensitivity` on a persona drives a controlled
  barge-in. Against an external agent it instead measures that agent's real
  barge-in / turn-taking behavior.

  **3. Latency is measured end-to-end instead.** Calibrate measures a wall-clock
  response latency from the simulator side, which works for external agents in
  place of the per-processor timings above.
</Note>

## Contrast with external text agents

Calibrate also supports connecting to an external **text** agent over HTTP for `--type text` simulations (see [Agent Connections](/core-concepts/agent-connections)). The two are different transports for different purposes:

| Aspect            | External text agent (HTTP)                                    | External voice agent (WebSocket)                       |
| ----------------- | ------------------------------------------------------------- | ------------------------------------------------------ |
| Simulation type   | `--type text`                                                 | `--type voice`                                         |
| Transport         | HTTP request/response                                         | WebSocket frame protocol (pipecat)                     |
| Medium            | Text only                                                     | Real audio                                             |
| Config key        | `agent_url` over `http(s)://`                                 | `agent_url` over `ws(s)://`                            |
| Captured metrics  | `tool_calls`, cost, and token metrics                         | No tool-call or cost metrics                           |

## Example config

A minimal external voice-agent config — note the absence of `system_prompt`, `tools`, `stt`, `tts`, and `llm`:

```json
{
  "agent_url": "ws://localhost:8765",
  "agent_serializer": "protobuf",
  "personas": [
    {
      "label": "friendly customer",
      "characteristics": "You are a friendly customer who wants to check your order status. Your order ID is ORD-12345. You are polite and patient.",
      "gender": "neutral",
      "language": "english"
    }
  ],
  "scenarios": [
    {
      "name": "simple order inquiry",
      "description": "Ask about your order status directly and provide your order ID right away."
    }
  ],
  "evaluators": [
    {
      "id": "order-resolved-id",
      "name": "order_resolved",
      "system_prompt": "You are a highly accurate evaluator assessing a conversation between a customer support agent and a simulated user. You will be given the chat history of the conversation. Mark True if the agent looked up and clearly communicated the order status to the customer.",
      "judge_model": "openai/gpt-4.1"
    }
  ],
  "settings": {
    "agent_speaks_first": true,
    "max_turns": 5
  }
}
```

Run it as a normal voice simulation:

```bash
calibrate simulations --type voice -c config.json -o ./out
```
