Instead of defining an agent inside Calibrate, you can point the CLI at an agent you've already deployed. Set `agent_url` in your config JSON — the scheme decides the connection type.

Pick the connection that matches your agent:

<CardGroup cols={2}>
  <Card title="Chat agent" icon="message" href="/cli/agent-connections/chat">
    Standard HTTP chat, including OpenAI-compatible APIs. For LLM tests and
    `--type text` simulations.
  </Card>
  <Card
    title="Outbound voice agent"
    icon="phone-arrow-up-right"
    href="/cli/agent-connections/outbound-voice"
  >
    Real-audio voice over a pipecat WebSocket. For `--type voice` simulations.
  </Card>
</CardGroup>

| Type             | Description                                          | Required fields            |
| ---------------- | --------------------------------------------------- | -------------------------- |
| `chat`           | Standard HTTP chat, including OpenAI-compatible APIs | `agent_url` (`http(s)://`) |
| `outbound-voice` | Pipecat voice agent over WebSocket                  | `agent_url` (`ws(s)://`)   |

## Verify your connection

Confirm Calibrate can reach your agent before running a simulation.

**Chat agent** — checks reachability and response format:

```bash
calibrate simulations --verify --agent-url https://your-agent.example.com/chat \
  --agent-headers '{"Authorization": "Bearer YOUR_API_KEY"}'
```

**Outbound voice agent** — Calibrate opens the WebSocket and confirms the handshake automatically before each voice run. This is a reachability check only; it does not confirm the frame protocol or serializer is compatible.

<Note>
  Pass `--skip-verify` to a run to bypass the pre-run connection check — useful
  when you've already verified the agent or want to run against an endpoint that
  rejects the check.
</Note>
