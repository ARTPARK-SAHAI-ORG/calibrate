Select a provider by its vendor name or by its provider ID.

| You pass               | Calibrate runs     |
| ---------------------- | ------------------ |
| `-p sarvam`            | `sarvam-saaras-v3` |
| `-p sarvam-saaras-v4`  | `sarvam-saaras-v4` |

provider ID runs one specific model. Calibrate stores the results in a folder

## Realtime streaming providers

These providers stream audio to a realtime transcription API.

| Provider ID                  | Model                                                 | API key            | Languages                               |
| ---------------------------- | ----------------------------------------------------- | ------------------ | --------------------------------------- |
| `deepgram-flux`              | flux-general-en (English), flux-general-multi (Hindi) | `DEEPGRAM_API_KEY` | English, Hindi                          |
| `openai-gpt-live-transcribe` | gpt-live-transcribe                                   | `OPENAI_API_KEY`   | English, Hindi, Kannada, Marathi, Tamil |
| `openai-gpt-transcribe`      | gpt-transcribe                                        | `OPENAI_API_KEY`   | All supported languages                 |
| `sarvam-saaras-v4-realtime`  | saaras:v4                                             | `SARVAM_API_KEY`   | All supported languages                 |
| `sarvam-saaras-v3-realtime`  | saaras:v3-realtime                                    | `SARVAM_API_KEY`   | All supported languages                 |
| `sarvam-saaras-v4`           | saaras:v4                                             | `SARVAM_API_KEY`   | All supported languages                 |
| `cartesia-ink-preview`       | ink-preview                                           | `CARTESIA_API_KEY` | English, Hindi                          |

`deepgram-flux` runs a different model for each language, so Calibrate stores
its results under the model it ran: the folder `deepgram-flux-general-en` for
English and `deepgram-flux-general-multi` for Hindi. Every other provider
stores its results in a folder named after its provider ID.

On the pipeline engine, `sarvam-saaras-v4-realtime` and
`sarvam-saaras-v3-realtime` use Sarvam's realtime endpoint, where Sarvam's
server decides when the speaker has stopped, so the final transcript arrives
only after Sarvam's own silence window. `sarvam-saaras-v4` runs the same
saaras:v4 model on Sarvam's streaming endpoint, the one `sarvam-saaras-v3`
uses: Calibrate's voice detection decides when the speaker has stopped and asks
Sarvam for the final transcript straight away.

`deepgram-flux` and `cartesia-ink-preview` cover English and Hindi only.
`openai-gpt-live-transcribe` covers the languages OpenAI lists for
gpt-live-transcribe. `openai-gpt-transcribe` auto-detects any language outside
OpenAI's list, so it runs every language Calibrate supports. For a language a
provider does not cover, Calibrate rejects the run and suggests another
provider:

| Provider ID                  | Use instead             |
| ---------------------------- | ----------------------- |
| `deepgram-flux`              | `deepgram-nova-3`       |
| `openai-gpt-live-transcribe` | `openai-gpt-transcribe` |
| `cartesia-ink-preview`       | `cartesia-ink-whisper`  |

## Language-specific models

Some providers use different models for specific languages:

| Provider   | Language | Model   |
| ---------- | -------- | ------- |
| **Google** | Sindhi   | chirp-2 |

<Note>
  Google STT uses `chirp-2` model for Sindhi, instead of the default `chirp-3`.
  This is handled automatically by Calibrate.
</Note>

<Note>
  Gemini has no dedicated STT endpoint. Transcription runs through the Gemini
  multimodal model (`gemini-3.5-flash`) using the Gemini API.
</Note>
